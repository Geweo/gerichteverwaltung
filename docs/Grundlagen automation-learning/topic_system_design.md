# topic_system-design.md

## Zweck dieses Dokuments

Dieses Dokument sammelt **thematisches Wissen** zum Thema **Systemdesign des MD‑basierten Wissens‑ und Lernsystems**.

Im Gegensatz zu Sessions ist dieses Dokument:
- **zeitlos**
- **thematisch fokussiert**
- **strukturiert**, aber **nicht bewertend**

Es dient als **Wissensanker** für alle zukünftigen Sessions und Analysen zu diesem Thema.

---

## Abgrenzung

**Dieses Dokument ist nicht:**
- eine Session
- eine Analyse
- eine Schwächen- oder Lösungsableitung

**Dieses Dokument ist:**
- ein strukturierter Wissensraum
- eine Sammlung stabiler Konzepte

---

## Kernkonzepte

### 1. Trennung von Ebenen

Das System unterscheidet strikt zwischen:
- **Input** (Beobachtung)
- **Analyse** (Vergleich)
- **Abstraktion** (Schwächen, Lösungen)
- **Steuerung** (Regeln, Overview)

Diese Trennung verhindert vorschnelle Bewertungen und sorgt für saubere Ableitungen.

---

### 2. Pipeline-Denken

Wissen fließt **gerichtet**:

```text
Session → Summary → Schwäche → Lösung → Regel → bessere Session
```

Rücksprünge sind nicht erlaubt, nur neue Durchläufe.

---

### 3. Schwächen als Muster, nicht als Fehler

Schwächen werden verstanden als:
- wiederkehrende Muster
- systemische Ursachen
- Ansatzpunkte für Verbesserung

Nicht als:
- Schuldzuweisung
- Einzelfehler

---

### 4. Lösungen vor Regeln

Regeln entstehen nur, wenn:
- eine Lösung wirkt
- sie wiederholt validiert wurde

So wird vermieden, dass Regeln auf Annahmen basieren.

---

### 5. Explizitheit als Qualitätshebel

Explizite Ziele, Strukturen und Regeln:
- reduzieren Missverständnisse
- entlasten Denken
- erhöhen Reproduzierbarkeit
