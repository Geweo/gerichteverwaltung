# Lokales Setup (Local) – Ernährbär

Für **Local** nutzen wir: lokales **Supabase** (`supabase start`), **LocalStack S3** für PDF-Upload, **Postgres** und **Ollama** in Docker.  
**Dev/Prod** nutzen Supabase Cloud und Supabase Storage – **kein** LocalStack, **kein** lokales Supabase.

---

## 1. Voraussetzungen

- [Docker](https://docs.docker.com/get-docker/) (Postgres, Ollama, LocalStack)
- [Supabase CLI](https://supabase.com/docs/guides/cli) (`supabase start`)
- [.NET 9 SDK](https://dotnet.microsoft.com/download)
- [Node.js 20+](https://nodejs.org/) und [pnpm](https://pnpm.io/)
- Optional: [AWS CLI](https://aws.amazon.com/cli/) für `scripts/ensure-localstack-bucket.*` (S3-Bucket anlegen)

---

## 2. Docker: Postgres, Ollama, LocalStack

```bash
docker-compose up -d
```

- **postgres** (5432): App-DB `ernaehrbar`
- **ollama** (11434): LLM (Rezeptgenerierung)
- **localstack** (4566): S3 für PDF-Upload

### S3-Bucket für Uploads (einmalig)

Nach dem Start von LocalStack:

```powershell
# Windows
.\scripts\ensure-localstack-bucket.ps1
```

```bash
# Linux/macOS
chmod +x scripts/ensure-localstack-bucket.sh
./scripts/ensure-localstack-bucket.sh
```

Falls AWS CLI fehlt, Bucket manuell anlegen (z.B. mit [awslocal](https://github.com/localstack/awscli-local)):

```bash
awslocal s3 mb s3://ernaehrbar-uploads --region eu-central-1
```

### Ollama-Modell (einmalig)

```bash
docker exec ollama-ai ollama pull llama3.2
# oder: .\install-ollama-model.ps1
```

## 3. Supabase lokal (nur Local)

**Voraussetzung:** Supabase CLI muss installiert sein. Siehe [SUPABASE_CLI_SETUP.md](./SUPABASE_CLI_SETUP.md) für Installationsanleitung.

Im Projektroot:

```bash
supabase start
```

Dabei wird `supabase/config.toml` verwendet. In der Ausgabe stehen u.a.:

- **API URL:** `http://127.0.0.1:54321`
- **anon key:** `eyJ...`
- **service_role key:** `eyJ...`

Studio: `http://127.0.0.1:54323` (Nutzer anlegen, Keys prüfen).

**Wichtig:** Für **Dev/Prod** wird `supabase start` **nicht** verwendet; dort nutzt ihr euer Supabase-Cloud-Projekt.

**Siehe auch:** [SUPABASE_CLI_SETUP.md](./SUPABASE_CLI_SETUP.md) für detaillierte Anleitung.

## 4. Backend (ASPNETCORE_ENVIRONMENT=Local)

Die Konfiguration für **Local** liegt in `appsettings.Local.json` (Supabase lokal, Storage = LocalStack).  
Profil **Local** setzt `ASPNETCORE_ENVIRONMENT=Local`.

### EF-Migrationen (einmalig)

```bash
cd server
dotnet ef database update --project Ernaehrbar.Adapters.Infrastructure --startup-project Ernaehrbar.Api
```

Verwendet die `DefaultConnection` aus `appsettings.json` (Postgres localhost:5432).

### API starten

- In der IDE: Startprofil **Local** wählen, oder  
- Terminal:

```bash
cd server
$env:ASPNETCORE_ENVIRONMENT="Local"
dotnet run --project Ernaehrbar.Api
```

Die API nutzt dann:

- Supabase: `http://127.0.0.1:54321` (JwksUrl: `http://127.0.0.1:54321/auth/v1/.well-known/jwks.json`)
- Storage: LocalStack S3 `http://localhost:4566`, Bucket `ernaehrbar-uploads`

## 5. Frontend (Supabase lokal)

`client/.env` bzw. `client/.env.local` mit den Werten aus `supabase start`:

```env
VITE_SUPABASE_URL=http://127.0.0.1:54321
VITE_SUPABASE_ANON_KEY=<anon key aus supabase start>
```

Dann:

```bash
cd client
pnpm install
pnpm dev
```

## 7. Dev/Prod (ohne LocalStack, ohne lokales Supabase)

- **Supabase:** Cloud-Projekt (`appsettings.json`: `Supabase:Url`, `Supabase:JwksUrl`).
- **Storage:** Supabase Storage (später über IFileStorage); **kein** LocalStack.
- **Ollama:** optional; typisch OpenAI/Anthropic oder anderer LLM.
- **ASPNETCORE_ENVIRONMENT:** `Development` oder `Production` (dann **kein** `appsettings.Local.json`).
