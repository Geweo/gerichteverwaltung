# Datenbank-Erweiterungen – Empfehlungen

**Datum:** 2026-01-24  
**Zweck:** Konkrete Implementierungsempfehlungen für fehlende DB-Felder

---

## 🎯 Priorität 1: Recipe-Erweiterungen

### Problem
Komponenten-Dokumentation erwähnt:
- "Type: generiert / upload" → fehlt in DB
- "Gerichttyp: Frühstück / Mittag / Abend" → fehlt in DB
- "Wiederholungszyklus: alle X Wochen" → fehlt in DB

### Lösung

#### 1. RecipeSource Enum hinzufügen

**Datei:** `server/Ernaehrbar.Parts/Ports/ILLMService.cs` (oder neue Datei)

```csharp
namespace Ernaehrbar.Parts.Ports;

/// <summary>
/// Source/Origin of a recipe.
/// </summary>
public enum RecipeSource
{
    /// <summary>
    /// Generated by AI/LLM.
    /// </summary>
    Generated = 1,

    /// <summary>
    /// Uploaded from PDF/image.
    /// </summary>
    Upload = 2,

    /// <summary>
    /// Manually created by user.
    /// </summary>
    Manual = 3
}
```

#### 2. Recipe Entity erweitern

**Datei:** `server/Ernaehrbar.Adapters.Infrastructure/Data/Entities/Recipe.cs`

```csharp
// Nach CookingTimeMinutes hinzufügen:

/// <summary>
/// Source/Origin of the recipe (Generated, Upload, Manual).
/// </summary>
public RecipeSource Source { get; set; } = RecipeSource.Manual;

/// <summary>
/// Meal category this recipe is typically used for (nullable, can be flexible).
/// </summary>
public MealCategory? MealCategory { get; set; }

/// <summary>
/// Repeat cycle in weeks (e.g., 2 = repeat every 2 weeks).
/// Null means no automatic repetition.
/// </summary>
public int? RepeatCycleWeeks { get; set; }
```

#### 3. Migration erstellen

```bash
cd server
dotnet ef migrations add AddRecipeSourceAndMealCategory --project Ernaehrbar.Adapters.Infrastructure --startup-project Ernaehrbar.Api
```

**Migration-Inhalt:**
```csharp
migrationBuilder.AddColumn<int>(
    name: "Source",
    table: "Recipes",
    type: "integer",
    nullable: false,
    defaultValue: 3);  // Manual

migrationBuilder.AddColumn<int>(
    name: "MealCategory",
    table: "Recipes",
    type: "integer",
    nullable: true);

migrationBuilder.AddColumn<int>(
    name: "RepeatCycleWeeks",
    table: "Recipes",
    type: "integer",
    nullable: true);
```

## 🎯 Priorität 3: RecipeDrafts für Review-Prozess

### Problem
Upload/KI-Generierung sollte nicht direkt in `Recipes` landen, sondern erst nach Review.

### Lösung

#### 1. DraftStatus Enum hinzufügen

**Datei:** `server/Ernaehrbar.Adapters.Infrastructure/Data/Entities/RecipeDraft.cs` (neu)

```csharp
namespace Ernaehrbar.Adapters.Infrastructure.Data.Entities;

/// <summary>
/// Status of a recipe draft in the review process.
/// </summary>
public enum DraftStatus
{
    /// <summary>
    /// Pending review.
    /// </summary>
    Pending = 1,

    /// <summary>
    /// Approved and converted to Recipe.
    /// </summary>
    Approved = 2,

    /// <summary>
    /// Rejected and discarded.
    /// </summary>
    Rejected = 3
}
```

#### 2. RecipeDraft Entity erstellen

**Datei:** `server/Ernaehrbar.Adapters.Infrastructure/Data/Entities/RecipeDraft.cs` (neu)

```csharp
namespace Ernaehrbar.Adapters.Infrastructure.Data.Entities;

/// <summary>
/// Draft recipe pending review (from Upload or AI generation).
/// </summary>
public class RecipeDraft : BaseGroupEntity
{
    /// <summary>
    /// Status in review process.
    /// </summary>
    public DraftStatus Status { get; set; } = DraftStatus.Pending;

    /// <summary>
    /// Source of the draft (Generated or Upload).
    /// </summary>
    public RecipeSource Source { get; set; }

    /// <summary>
    /// Original recipe data (JSON from AI or extracted from PDF).
    /// </summary>
    public string? OriginalData { get; set; }

    /// <summary>
    /// User who created the draft.
    /// </summary>
    public int CreatedByUserId { get; set; }

    /// <summary>
    /// Navigation property to creator.
    /// </summary>
    public User CreatedByUser { get; set; } = null!;

    /// <summary>
    /// User who reviewed the draft (if reviewed).
    /// </summary>
    public int? ReviewedByUserId { get; set; }

    /// <summary>
    /// Navigation property to reviewer.
    /// </summary>
    public User? ReviewedByUser { get; set; }

    /// <summary>
    /// Date when reviewed.
    /// </summary>
    public DateTime? ReviewedAt { get; set; }

    // Recipe-Daten (dupliziert für Review)
    public required string Name { get; set; }
    public string? Description { get; set; }
    public string? Instructions { get; set; }
    public MealCategory? MealCategory { get; set; }
    public List<string> Tags { get; set; } = new();
    public List<RecipeIngredient> Ingredients { get; set; } = new();
}
```

#### 2. Notification Entity erstellen

namespace Ernaehrbar.Adapters.Infrastructure.Data.Entities;

/// <summary>
/// User notification.
/// </summary>
public class Notification : BaseEntity
{
    /// <summary>
    /// User who receives the notification.
    /// </summary>
    public int UserId { get; set; }

    /// <summary>
    /// Navigation property to user.
    /// </summary>
    public User User { get; set; } = null!;

    /// <summary>
    /// Type of notification.
    /// </summary>
    public NotificationType Type { get; set; }

    /// <summary>
    /// Notification message.
    /// </summary>
    public required string Message { get; set; }

    /// <summary>
    /// Whether the notification has been read.
    /// </summary>
    public bool IsRead { get; set; }

    /// <summary>
    /// Date when read (if read).
    /// </summary>
    public DateTime? ReadAt { get; set; }

    /// <summary>
    /// Optional link/action (e.g., recipe ID, meal plan ID).
    /// </summary>
    public string? ActionLink { get; set; }
}

## 🎯 Priorität 5: UploadTasks

### Problem
Keine DB-Struktur für Upload-Status-Tracking.

### Lösung

#### 1. TaskStatus Enum hinzufügen

**Datei:** `server/Ernaehrbar.Adapters.Infrastructure/Data/Entities/UploadTask.cs` (neu)

```csharp
namespace Ernaehrbar.Adapters.Infrastructure.Data.Entities;

/// <summary>
/// Status of an upload/background task.
/// </summary>
public enum TaskStatus
{
    Pending = 1,
    Processing = 2,
    Completed = 3,
    Failed = 4
}
```

#### 2. UploadTask Entity erstellen

**Datei:** `server/Ernaehrbar.Adapters.Infrastructure/Data/Entities/UploadTask.cs` (neu)

```csharp
namespace Ernaehrbar.Adapters.Infrastructure.Data.Entities;

/// <summary>
/// Background task for file upload processing.
/// </summary>
public class UploadTask : BaseGroupEntity
{
    /// <summary>
    /// User who uploaded the file.
    /// </summary>
    public int UserId { get; set; }

    /// <summary>
    /// Navigation property to user.
    /// </summary>
    public User User { get; set; } = null!;

    /// <summary>
    /// Original file name.
    /// </summary>
    public required string FileName { get; set; }

    /// <summary>
    /// File path in storage (S3/Supabase).
    /// </summary>
    public required string FilePath { get; set; }

    /// <summary>
    /// Status of the task.
    /// </summary>
    public TaskStatus Status { get; set; } = TaskStatus.Pending;

    /// <summary>
    /// Error message (if failed).
    /// </summary>
    public string? Error { get; set; }

    /// <summary>
    /// Resulting recipe draft ID (if successful).
    /// </summary>
    public int? RecipeDraftId { get; set; }

    /// <summary>
    /// Navigation property to recipe draft.
    /// </summary>
    public RecipeDraft? RecipeDraft { get; set; }
}
```
